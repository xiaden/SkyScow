# Track work with issues and projects

Plan and triage work, and link code to the issues it resolves.

## Issues
- Use issues to track bugs, tasks, and feature requests with a clear title and body.
- Assign an owner, a milestone, and labels to make triage fast.
- Reference issues from commits and PRs (for example `Closes #123`) to auto-close on merge and keep traceability.
- Link related issues with cross-references so context is discoverable.

## Projects
- Use GitHub Projects (board views) to group issues and PRs into columns by status.
- Keep columns aligned with the team workflow (todo, in progress, in review, done).
- Add issue fields (priority, estimate, owner) only when they reduce triage friction; avoid project-management sprawl.

## Hygiene
- Close stale or duplicate issues; leave a short comment when closing so the decision is auditable.
- Prefer one issue per actionable change so history stays attributable.
